## Common block copied unchanged; only JOUT1.1/.2 move behind the window

Every ref, value, LCSC code and net of zudo-pd `board_p_r3_spec.py` @3ac13d46 is copied unchanged. `check_rnext.py` enforces this:

- Its block-parity list is empty.
- A changed R12 value and a moved JOUT1 pin were both caught as mutations.

The only changes are:

1. JOUT1.1/.2 move from `VBUS_OUT` to `LED_OUT`, the window output.
2. JOUT1 keeps the LED footprint nickname for the same PZ254V-11-06P (C492405) part.
3. Window parts U4, U5, C40–C42 and R30–R39 are added, plus two virtual ERC power flags.

JOUT1 pins 3 ATT, 4 PDOK and 5/6 GND are unchanged, so the 2 assembled Board Ls mate unchanged.

## The window after Q1: OFF at ≤ 12.755 V, ON needs ≥ 14.0 V, OV trips at 16.49–17.95 V

The window is `../board-p-stusb-window-subcircuit` renumbered. U4 is a TPS259474LRPWR eFuse and U5 a TPS3701DDCT monitor. Both sense `VBUS_OUT`, after Q1 (DMP3036).

| Item | L2 result (0.1 % + TCR + soldering + endurance, V196 model) |
| --- | --- |
| Monitor U5 INA falling (OFF guaranteed) | ≤ 12.755 V; +0.155 V margin over the 12.6 V reject level |
| Monitor rising (needed for ON) | ≤ 13.999 V |
| U4 UV rising (no QINH leakage now) | 12.412–13.496 V |
| U4 OV rising / falling minimum | 16.485–17.948 V / 14.992 V |

Two changes from the standalone sub-circuit:

- **QINH, RG, RB and RBE are dropped.** VBUS_EN_SNK already gates Q1, so Q1 is the contract gate.
  - Keeping RG from the VBEN node to the window input would be harmful. With VBEN released, the VBUS_P–R11–R12–RG path carries about 49 µA. That gives Q1 a VGS of about −7 V and turns it on.
  - An RG to VBUS_P would be harmless, but it would only duplicate Q1.
- **The SMAJ20A input TVS is dropped.** See the next section.

## SMAJ20A clamp above 28 V: removed and handled the same way as PD gate L7, which stays open

- The LED derivative inherits the common front end: D5 TVS2200DRVR at the connector, then U3 LM74700 + Q3 ideal diode, then the U2 TPS16630 eFuse, giving the protected node `VBUS_P`.
  - OVP is 174k/10k, 21.60–22.56 V rising.
  - There is 100 µF bulk on the protected node.
- The SMAJ20A (VC 32.4 V) appears nowhere on this board.
- U4 IN (28 V abs max) and U5 VDD (40 V abs max) sit on `VBUS_OUT`, which follows `VBUS_P` through Q1. Their surge exposure is therefore the STUSB4500 VDD exposure.
- That exposure is the PD worker's gate L7, still **OPEN / BLOCKING**:
  - The only guaranteed bound is the TVS2200 clamp: 28.0 V at 27 °C and 28.35 V at 125 °C, a margin of 0 / −0.35 V.
  - On typical values, the node reaches 25.1–29.6 V depending on C3 ESR.
- No LED-specific number is claimed.
- One LED-only option is recorded, **not adopted**: lower the front-end OVP divider for the 15 V-only product. A factory-image 20 V contract would then latch the eFuse OFF. That is acceptable for a fail-OFF lamp, but it changes a common-block value. It needs PD worker arithmetic and a user decision.
- Board L keeps its own D10 SMAJ20A on V15 (reused hardware). The window OV holds Board L at ≤ 17.95 V in steady state.

## Per-product parameter pair: PDO2 current and U4 current limit (R38) move together

| OPTION | NVM I_SNK_PDO2 | R38 (U4 ILM) | Note |
| --- | --- | --- | --- |
| `I1A5` (**default, pending user**) | 0101b, 1.50 A | 3.32 k 1 % (0603WAF3321T5E, LCSC unverified) | TI SLVSFC9C tabulated point: 0.850–1.150 A at exactly 3.32 k. Above Board L F1's 0.75 A hold current. Resistor tolerance is not in the TI band |
| `I3A` (alternative) | 1011b, 3.00 A | 1.27 k 1 % RC0603FR-071K27L C245930 | V196 value. It falls between tabulated points; the nominal limit is about 2.6 A, so U4 limits below the 3 A contract |

The rest of the NVM text image follows common block §6.2:

- SNK_PDO_NUMB = 2
- V_SNK_PDO2 = 15.00 V
- POWER_ONLY_ABOVE_5V = 1
- POWER_OK_CFG = 10b

Nothing is programmed. The byte map and write sequence are DS12499 gaps (common block §7).

## Native checks: netlist matches the spec; ERC not clean (see checks/)

The checks ran in KiCad 10.0.6 (`kicad/kicad@sha256:18693567…`), serialized with `flock /tmp/kicad-native.lock`. Details are in `checks/NATIVE-RUN.txt`, `checks/erc.json` and `checks/board-p-rnext.net`.

| Check | Result |
| --- | --- |
| Netlist export → `verify_netlist.py` | **PASS**: 36 expected nets + 17 single-pin NC nets, 203 nodes, exact match to the spec |
| ERC errors | **0**. The first run had 2 `power_pin_not_driven` errors (U4 IN, U4 GND). Two stock PWR_FLAGs (#FLG01 on GND, #FLG02 on VBUS_OUT) resolved them |
| ERC warnings | **67**, exit 5 because `--exit-code-violations` counts warnings. 54 `footprint_link_issues`: footprints are names only. 13 `pin_to_pin` on D5 (TVS2200) and JOUT1, whose library pins are "unspecified" type. The PD r3 draft run on a scratch copy shows the same class (33 pin_to_pin) |
| Not a PASS | ERC is not clean. Nothing here is a DRC, a layout or a validation |

`verify_netlist.py` now skips `#`-prefixed virtual refs, which KiCad never exports. Canonical boards are unaffected.
